# 语音克隆平台接入方案

> 目标：把 TTS 语音克隆聚合平台接入 `<AI_ROOT>` 模型服务管理平台（service-entry / manager-core 体系），成为与 vllm-manager、llama-manager 并列的语音后端。
> 读者：管理平台工程师。文中"TTS 侧改造"可以由 TTS 平台维护方（Claude 会话）完成，"管理平台侧"为需要你们做的工作。
> 日期：2026-08-26

> 平台代码位于 `<AI_ROOT>\tts-platform`；统一入口已实现 `/gateway/tts/` 流式反代、客户端 Key/限流、控制台引擎状态卡片、OpenAI Audio 兼容转发及本机限定的模型生命周期管理。模型与 Python 环境使用可配置的 `<TTS_RUNTIME_ROOT>`，默认位于 `<AI_ROOT>\tts-runtime`。

---

## 1. 被接入方现状（TTS 平台）

### 1.1 组件与端口

| 组件 | 端口 | 技术栈 | 协议 | 说明 |
|---|---|---|---|---|
| TTS 网关 | **7000** | Python / FastAPI | REST + 静态文件 | 唯一对外入口，聚合下面所有 worker，自带网页 UI |
| Chatterbox worker | 7011 | FastAPI（venv: `<TTS_RUNTIME_ROOT>\envs\chatterbox`） | `POST /tts` multipart | Chatterbox Multilingual V3，0.5B |
| Qwen worker | 7012 | FastAPI（venv: `<TTS_RUNTIME_ROOT>\envs\qwen`） | `POST /tts` multipart；`POST /translate` JSON | Qwen3-TTS 1.7B 克隆 + Qwen3-4B 翻译兜底 |
| Fish worker | 7013 | fish-speech 官方 api_server（venv: `<TTS_RUNTIME_ROOT>\envs\fish`） | `POST /v1/tts`（**ormsgpack**）；`GET /v1/health` | Fish S2 Pro 4B，唯一非 multipart 协议 |
| Step worker | 7014 | Docker 容器 `step-audio`（镜像 `step-audio-editx:ffmpeg`，内含 vLLM） | `POST /tts` multipart | Step-Audio-EditX 3B，仅 Linux 容器可跑 |
| VoxCPM worker | 7015 | FastAPI（venv: `<TTS_RUNTIME_ROOT>\envs\voxcpm`） | `POST /tts` multipart | VoxCPM 2，可选参考音色，30 种语言 |
| Qwen VoiceDesign worker | 7016 | FastAPI（复用 qwen venv） | `POST /tts` multipart | 按文字描述设计声音，无需参考音频 |

- 所有服务只监听 `127.0.0.1`（Step 容器经 Docker 端口映射到 127.0.0.1:7014）。
- 网关调用 worker 超时 600s（首次请求才加载模型，冷启动 30s~5min，热路径 3~40s）。
- 启动脚本：`<AI_ROOT>\tts-platform\scripts\start_all.ps1`（幂等，可重复执行）；单独组件有各自 `start_*.ps1`。

### 1.2 网关 REST API（接入面）

Base：`http://127.0.0.1:7000`

| 方法与路径 | 请求 | 响应 | 备注 |
|---|---|---|---|
| `GET /api/engines` | – | `[{id,name,type,available,detail}]` | 实时健康探测，1~2s 返回，可直接作为健康检查 |
| `POST /api/voices` | multipart：`file`(音频)、`name`、`ref_text` | `{id,name,ref_text,created}` | 任意格式音频，内部 ffmpeg 转 24k 单声道 wav。**建议限 ≤10MB** |
| `GET /api/voices` | – | 音色列表 | |
| `GET /api/voices/{id}/audio` | – | `audio/wav` | |
| `DELETE /api/voices/{id}` | – | `{ok}` | |
| `POST /api/translate` | JSON：`{text,target_language}` | `{translation,target_language,model}` | 任意目标语种。级联：本地平台网关(5176) → DashScope → 小米 → 本地 Qwen3-4B |
| `GET /api/models` | – | `{items:[...]}` | 安装、服务、显存、忙碌与可用操作状态 |
| `POST /api/models/{id}/actions/{action}` | – | `202` 操作状态 | `install/start/wake/unload/stop`，统一入口仅允许本机直连 |
| `POST /api/tts` | JSON：`{engine, text, voice_id, language, speed, emotion, style}` | `{ok, engine, url, elapsed_ms}` | `url` 形如 `/outputs/xxx.wav`，需再 GET 一次取音频 |
| `GET /outputs/{file}` | – | `audio/wav` | 生成结果静态目录 |

`engine` 另新增 `voxcpm2` / `qwen_voice_design`。`language` 接受 `auto`、BCP-47 或语种名称，不再限定 `en`/`zh`；模型原生范围通过引擎元数据返回。
`speed` 0.5~2.0（ffmpeg 变速）；`emotion` ∈ {开心,兴奋,平静,悲伤,生气,耳语}；`style` 自由文本仅 `mimo_api` 生效；`language` 目前用 `en`/`zh`。
错误统一为 FastAPI 格式：`{"detail": "..."}`，状态码 400（参数）/ 502（引擎失败）。

### 1.3 当前安全状态（接入前必读）

- 网关**无鉴权**，依赖只绑 127.0.0.1。经管理平台暴露到局域网前，必须先完成 §3 阶段二。
- `voices/` 存的是用户真实录音（生物特征数据），不应随平台日志外发。
- Chatterbox 输出内嵌 PerTh 不可听水印；其余引擎无水印。

## 2. 接入后拓扑

```
客户端(OpenWebUI / SDK / 浏览器)
        │
        ▼
service-entry :5176  ──  /gateway/auto/openai/v1 ──► vllm-manager :5177 / llama-manager :5178（现状）
        │
        └─ /gateway/tts/* ──► TTS 网关 :7000 ──► workers :7011~7016 + 小米/DashScope API
```

同时保留反向依赖：TTS 网关的翻译已优先调用 `http://127.0.0.1:5176/gateway/auto/openai/v1`（fleet 有模型时自动使用，无需配置）。注意别做成环路：管理平台转发给 7000 的请求路径中不含 chat/completions，不会回流。

## 3. 分阶段接入方案

### 阶段一：反代 + 控制台卡片（预计 0.5 天）

管理平台侧（service-entry/server.js）：

1. 新增路由前缀 `/gateway/tts/`，剥掉前缀后原样转发到 `http://127.0.0.1:7000/`。要点：
   - **转发 `/api/*` 和 `/outputs/*` 两类路径**（客户端拿到 `url` 后会二次 GET `/gateway/tts/outputs/...`）。
   - multipart 直接流式透传，不要缓冲整个 body 再转发。
   - 上游超时 ≥ **600s**（冷启动加载模型）；对 `/api/engines`、`/api/voices` 可以用 10s。
   - 响应中 `url` 字段是根相对路径，两种处理任选：反代层把 `"/outputs/` 重写为 `"/gateway/tts/outputs/`；或 TTS 侧加环境变量 `PUBLIC_PREFIX` 自己拼好（TTS 侧可改，见 §4）。
2. 控制台加"语音服务"卡片：状态取 `GET /api/engines`，展示每个引擎 available；卡片链接指向 `/gateway/tts/`（网页 UI 也会被反代，UI 内部全部用相对路径 fetch，多级路径下需验证，见 §4-3）。
3. 健康检查/保活：沿用 manager-core 健康检查器，探 `GET /api/engines`，任一引擎 available 即视为部分可用；全部 down 才标红。

### 阶段二：鉴权与统计对齐（预计 0.5~1 天）

- 管理平台侧：`/gateway/tts/*` 套用与 `/gateway/auto/*` 相同的 key 校验（复用 manager-core 的 gateway-trust / access-log），Key 仍在管理器"服务提供"页生成，不必为语音单独发 key。
- 统计与计费：access-log 里对 TTS 请求记录建议字段：`engine`、`voice_id`、`chars=len(text)`、`elapsed_ms`（响应体里带）、结果状态。外部 API 引擎（mimo_api）有真实资金成本（按字符），如需分摊计费，挂 billing-client 时按字符计。
- TTS 侧（可由 TTS 维护方完成）：支持 `TTS_API_KEY` 环境变量，非空时校验 `Authorization: Bearer`，本机回环可配白名单——即管理平台转发时带上游 key 或内部 key 二选一，防止绕过 5176 直连 7000。

### 阶段三：OpenAI 兼容层（可选，预计 1 天）

让 OpenWebUI 等现成客户端把语音平台当 OpenAI TTS 用。**建议实现在 TTS 网关内**（Python 侧加一个路由即可），管理平台只多转发一个路径：

- `POST /v1/audio/speech`，映射：`model`→engine（如 `tts-fish`、`tts-chatterbox`）、`voice`→voice_id、`input`→text、`speed`→speed、`response_format` 仅支持 `wav`（其余 ffmpeg 转）。响应直接回音频流（OpenAI 语义），不走 `/outputs` 二段式。
- `GET /v1/models` 返回引擎列表（`tts-*` 前缀），方便客户端选择。
- 管理平台把 `/gateway/tts/openai/v1/*` 转发到 `7000/v1/*`，鉴权同阶段二。

### 阶段四：生命周期与显存协调（已实现）

- TTS 网关提供固定白名单的安装、启动、预加载、卸载与停止接口；服务入口对变更请求执行严格 localhost 校验。各 worker 日志写入 `tts-platform/logs/model-*.log`；Step 仍可用 `docker logs step-audio`。
- 显存预算（96GB 卡，与 27B fleet 共存）：fish ≈9GB（--half）、chatterbox ≈3GB、qwen worker ≈4GB（若触发本地翻译再 +9GB）、Step 容器 vLLM 预留 15%（≈15GB，`STEP_GPU_MEM_UTIL` 环境变量可调）。TTS 全家桶合计 ≈31GB 上限。
- Chatterbox、Qwen Base、Qwen VoiceDesign 和 VoxCPM 已支持服务内释放权重；Fish 与 Step 使用安全停止释放资源。忙碌模型拒绝卸载或停止。

## 5. 运维速查

| 事项 | 内容 |
|---|---|
| 一键启动 | `pwsh -File "<AI_ROOT>\tts-platform\scripts\start_all.ps1"`（幂等） |
| 配置 | `<AI_ROOT>\tts-platform\.env`（小米/DashScope Key、LOCAL_LLM_BASE 等） |
| 日志 | 各 worker 的最小化 pwsh 窗口 stdout；Step：`docker logs -f step-audio` |
| 模型/环境位置 | `<TTS_RUNTIME_ROOT>\`（hf 权重、envs、repos、models） |
| 常见故障 | 端口占用→start_all 会跳过已监听端口；Step 500→查 `docker logs`；首次请求超时→模型冷加载属正常，客户端超时需 ≥600s；显存不足→先降 `STEP_GPU_MEM_UTIL` 或停用 fish |
