# 模型目录、跨盘下载与迁移

在统一入口的“模型”页打开“管理存储与迁移”，或从 vLLM / llama.cpp 管理器的“模型库”进入“模型存储与迁移”。该页面用于本机文件管理；现有对外模型调用方式保持原有设置。

## 登记不同磁盘的模型

1. 点击“添加模型库 / 导入已有模型”，输入绝对目录，例如 `F:\AI\models`。
2. 若目录下面有多个模型文件夹，选择“模型库”。若输入的目录本身就是一个模型，选择“单个已有模型”。登记不会复制、移动或删除文件。
3. 可以勾选创建尚不存在的文件夹，或把模型库设为默认下载位置。两个管理器共享设置，下载表单也能逐次选择不同模型库。

原有 `models` 目录始终保留。离线磁盘保留登记，重新接入后可刷新。取消登记只移除管理入口，不删除磁盘文件。含迁移映射的目录须先处理映射才能取消登记。

选择专用文件夹，不要登记整个盘符或相互包含的模型库。嵌套目录链接不能越出已登记模型库。HF 缓存快照可能包含链接；应先导出为普通模型目录，再登记或迁移。该功能管理 vLLM / llama.cpp 的模型权重目录，HF 缓存和 TTS 运行环境仍使用各自的配置。

## 下载新模型

下载表单的“模型库”决定本次目标磁盘。后端重新获取 HF 文件清单，按目标盘的实际剩余空间检查容量；选中的 mmproj、draft 等附属文件计入预估与校验。

目标目录已有不相关文件时会阻止覆盖。平台发起过的同一模型、来源和精度可以继续下载；取消或暂停都保留已下载文件。HF 下载结束后检查模型完整性，默认按仓库提供的 SHA256 校验 LFS 文件；缺失或校验不符不会显示成功。用户关闭下载设置中的校验选项时会明确记录跳过。

需要授权的仓库仍需账号获得仓库访问权。ModelScope 使用其独立 CLI，无法保证与 HF 相同的容量预估和 LFS 校验。

若下载器无法启动，运行 `install-download-cli.cmd`。该脚本创建独立的 `venvs\download-cli` 环境并安装 HF 与 ModelScope 兼容版本；它不会修改推理环境。重启管理器后优先使用该下载器，显式设置的 `HF_CLI` / `MODELSCOPE_CLI` 仍优先。已有 `HF_HOME` 缓存及登录信息保留。也可运行：

```powershell
.\scripts\install-download-cli.ps1 -AiRoot '<AI_ROOT>' -PythonExe '<Python 3.10+ 的完整路径>'
```

## 迁移与回滚

1. 登记目标模型库，选择完整源模型目录、目标库和文件夹名称，点击“预览迁移”。目标名称必须未被占用；不会合并已有目录。
2. 预览显示文件数量、大小和剩余空间。目标盘需要完整副本空间及 10 GiB 余量。相关下载或挂载源目录的容器必须先结束；平台不会自动卸载模型。
3. 确认后，先复制到目标盘暂存目录，逐文件流式计算 SHA256 并读取目标副本核对。源目录变化、盘满、掉盘或校验失败会中止切换。可暂停，恢复后继续核验已复制的文件。
4. 全部通过后切换管理器中的模型路径。旧启动配置通过持久化路径映射找到新位置；Docker 启动命令挂载已登记且在线的模型库。此映射用于平台启动流程，外部手写脚本仍需自行改路径。
5. 原始文件继续保留。确认实际模型在新位置运行正常后，可选择“清理源文件并释放空间”，输入源目录完整路径再次确认。系统重验文件后才逐个删除已迁移文件；不会删除新加或改过的源文件。

清理前可“切回原路径”，两侧副本都保留。模型再次迁移后应按最近一轮开始回滚；清理原始副本时会检查当前映射的最终位置。清理中断后可重试。清理完成后不能直接恢复已删除的原始副本。

目录登记、路径映射和迁移清单保存在 `service-entry/data`，由平台配置备份涵盖。备份不包含巨大的模型权重。迁移副本和暂存文件不会因为取消任务被自动删除。
