# 模型目录、跨盘下载与迁移

在统一入口的“模型”页打开“管理存储与迁移”，或从 vLLM / llama.cpp 管理器的“模型库”进入“模型存储与迁移”。该页面用于本机文件管理；现有对外模型调用方式保持原有设置。

## 登记不同磁盘的模型

1. 点击“添加模型库 / 导入已有模型”，输入绝对目录，例如 `F:\AI\models`。
2. 若目录下面有多个模型文件夹，选择“模型库”。若输入的目录本身就是一个模型，选择“单个已有模型”。登记不会复制、移动或删除文件。
3. 可以勾选创建尚不存在的文件夹，或把模型库设为默认下载位置。两个管理器共享设置，下载表单也能逐次选择不同模型库。

原有 `models` 目录始终保留。离线磁盘保留登记，重新接入后可刷新。取消登记只移除管理入口，不删除磁盘文件。含迁移映射的目录须先处理映射才能取消登记。

选择专用文件夹，不要登记整个盘符或相互包含的模型库。嵌套目录链接不能越出已登记模型库。HF 缓存快照可能包含链接；应先导出为普通模型目录，再登记或迁移。该功能管理 vLLM / llama.cpp 的模型权重目录，HF 缓存和 TTS 运行环境仍使用各自的配置。

## 下载新模型

两个管理器的导航栏都有独立的“在线模型”页面，打开即显示搜索和筛选；下载页的“选择可运行模型”以及量化版本搜索也直接进入此页。

下载表单的“模型库”决定本次目标磁盘。后端重新获取 HF 文件清单，按目标盘的实际剩余空间检查容量；选中的 mmproj、draft 等附属文件计入预估与校验。

目标目录已有不相关文件时会阻止覆盖。平台发起过的同一模型、来源和精度可以继续下载；取消或暂停都保留已下载文件。HF 下载结束后检查模型完整性，默认按仓库提供的 SHA256 校验 LFS 文件；缺失或校验不符不会显示成功。用户关闭下载设置中的校验选项时会明确记录跳过。

需要授权的仓库仍需账号获得仓库访问权。ModelScope 使用其独立 CLI，无法保证与 HF 相同的容量预估和 LFS 校验。

若下载器无法启动，运行 `install-download-cli.cmd`。该脚本创建独立的 `venvs\download-cli` 环境并安装 HF 与 ModelScope 兼容版本；它不会修改推理环境。重启管理器后优先使用该下载器，显式设置的 `HF_CLI` / `MODELSCOPE_CLI` 仍优先。已有 `HF_HOME` 缓存及登录信息保留。也可运行：

```powershell
.\scripts\install-download-cli.ps1 -AiRoot '<AI_ROOT>' -PythonExe '<Python 3.10+ 的完整路径>'
```

## 迁移与回滚

1. 选择完整源模型目录，在“目标模型库路径”直接输入目标文件夹，例如 `F:\AI\models`，也可点已登记目录快捷按钮，或通过“浏览文件夹”选择磁盘和目录。初始位置采用当前默认模型库，手动输入不会被刷新覆盖。页面实时显示包含模型文件夹名称的最终保存位置。
2. 点击“预览迁移”。新路径无需提前登记，确认开始时才创建并登记为模型库，默认下载位置不会因此改变。目标模型文件夹必须未被占用；不会合并已有目录。模型库应为独立的专用目录，不能嵌套登记。
3. 预览显示文件数量、大小和剩余空间。目标盘需要完整副本空间及 10 GiB 余量。相关下载或挂载源目录的容器必须先结束；平台不会自动卸载模型。
4. 确认后，先复制到目标盘暂存目录，逐文件流式计算 SHA256 并读取目标副本核对。源目录变化、盘满、掉盘或校验失败会中止切换。可暂停，恢复后继续核验已复制的文件。
5. 全部通过后切换管理器中的模型路径。旧启动配置通过持久化路径映射找到新位置；Docker 启动命令挂载已登记且在线的模型库。此映射用于平台启动流程，外部手写脚本仍需自行改路径。
6. 原始文件继续保留。确认实际模型在新位置运行正常后，可选择“清理源文件并释放空间”，输入源目录完整路径再次确认。系统重验文件后才逐个删除已迁移文件；不会删除新加或改过的源文件。

清理前可“切回原路径”，两侧副本都保留。模型再次迁移后应按最近一轮开始回滚；清理原始副本时会检查当前映射的最终位置。清理中断后可重试。清理完成后不能直接恢复已删除的原始副本。

目录登记、路径映射和迁移清单保存在 `service-entry/data`，由平台配置备份涵盖。备份不包含巨大的模型权重。迁移副本和暂存文件不会因为取消任务被自动删除。

## 统一下载中心（模型中心）

模型下载由统一入口内的“模型中心”负责。统一入口会随管理器重启而保持运行，因此部署引擎或重启 vLLM / llama.cpp 管理器不再中断下载。两个管理器的“在线模型”和下载页面仍可使用，请求会转交给模型中心，原有页面与 `/api/download`、`/api/jobs` 保持不变。

- 来源：Hugging Face、hf-mirror 镜像和 ModelScope。搜索、仓库详情、文件清单和“下载计划”都在开始前给出；计划会列出将下载的文件、需要的空间、目标模型库，以及能否放进当前显卡（可放下、偏紧、需卸载到内存、放不下、未知）。
- 队列：全局排队，可调整顺序、暂停、继续、立即开始。默认在模型服务繁忙时等待，空闲后自动开始；目标磁盘空间不足时也会等待，腾出空间后继续。
- 断点续传：入口重启后，中断的下载自动继续，已暂停的保持暂停。遇到网络波动、限速等可重试的错误会自动退避重试，不可重试的错误（如未获授权、仓库 ID 不存在）会直接给出原因和建议操作。
- 令牌：Hugging Face 令牌只能在本机浏览器中输入。默认只用于本次下载并保存在内存中；勾选“记住”后加密保存在本机，下载结束即删除。入口重启后未保存的令牌需要重新输入，任务会显示“需要重新输入令牌”。令牌不会写入下载记录、日志或备份。
- 校验：完成后在后台逐文件检查大小和 SHA256，只删除有问题的文件，通过后才加入模型库并标记为“已就绪”。校验失败不会显示成功。
- 模型库：扫描已登记的模型库、HF 缓存和 ModelScope 缓存，给出来源（已确认、已检测、未确认、未知）、重复项和可用更新。删除需明确确认，且不会删除模型库根目录或正在使用的路径。
- 下载并运行：下载完成后可按计划启动引擎；已有同名部署时会先询问是否替换，模型中心不会自行停止或删除容器。

回退：在 `<AI_ROOT>\config\platform.json` 中设置 `hub.downloadsOwner` 为 `"manager"`（或设置环境变量 `AI_HUB_DOWNLOADS_OWNER=manager`）后重启统一入口与管理器，下载回到各管理器自己的旧流程。模型中心的状态保存在 `service-entry/data/hub`（下载队列、历史、模型库索引与日志），属于运行数据，不随发布包分发。
